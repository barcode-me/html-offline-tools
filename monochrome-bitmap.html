Monochrome bitmap

Turn a photo into a 1-bit black and white bitmap (.bmp), optionally hiding up to two 264-bit secrets in passphrase-scattered pixels, each with its own passphrase. Everything runs locally in your browser; nothing is uploaded or saved by the page.

Operation

On phones this also offers the camera.

Conversion

Dithering keeps shading in photos using patterns of dots. Threshold gives clean solid areas, best for text, logos and line art.

Gray levels below the threshold become black. Lower values give a lighter image.

Height follows the aspect ratio. Dithering looks best at the size the bitmap will be shown or printed.

Output format

The data URL is a lossless WebP encoded as text (data:image/webp;base64,…) that can be copied or turned into a QR code. Lossless WebP encoding needs a Chromium-based browser such as Chrome or Edge.

Hidden secrets (optional)

Up to two secrets, each with its own passphrase and its own half of the pixels, so they never overwrite each other. Neither passphrase reveals whether the other secret exists: an unused slot is filled with random bits.

Recovered bits

264 bits per slot, read from the pixels this passphrase selects. Every passphrase produces output for both slots and there is deliberately no way to tell which, if either, is real: your secret is at the start of its slot (slot 1 for secret 1, slot 2 for secret 2), followed by random padding. The other slot shows meaningless bits.

Show as

Output: Windows BMP, 1 bit per pixel, two-color palette (index 0 black, index 1 white), or a lossless WebP as a file and Base64 data URL; every WebP is decoded and compared pixel by pixel before it is offered. Transparent areas are placed on white. Colors are converted to gray with Rec. 709 luma weights. Large photos need more time and browser memory. QR codes hold the data URL in byte mode up to version 40 (177 × 177 modules); codes near that size are dense, so print them large and scan in good light.

BMP file layout

All multi-byte integers are little-endian. Rows are stored bottom to top, each padded with zero bits to a multiple of 4 bytes. In each byte the most significant bit is the leftmost pixel; a 1 bit is white.

Hidden data algorithm and format

This uses the same scattering as the LSB steganography page, but every pixel is one bit: instead of changing a least significant bit, a chosen pixel is set to black (0) or white (1). Pixels are numbered in raster order (left to right, top to bottom). Data is applied after dithering and inversion, so bits are absolute pixel colors.

  1. A random 16-byte salt is written, most significant bit first, into the first 128 pixels. It is shared by both slots and excluded from everything that follows. In a plain white or black area these 128 pixels at the top left are visible as a short noisy line.

  2. Each passphrase goes through PBKDF2-SHA-256 with the salt and 600,000 iterations; crypto.subtle.deriveBits returns 256 bits that become an AES-256-CTR key. Slot s (0 or 1) uses the keystream of zero bytes whose 128-bit counter block starts with s as a 64-bit big-endian number in the upper half and a 64-bit block counter in the lower half, consumed most significant bit first.

  3. The remaining M = width × height − 128 pixels form the pool. Slot 0 may only use pool indices 0, 2, 4, … and slot 1 only 1, 3, 5, …, so the slots never share a pixel. Within its half, each slot runs a partial Fisher–Yates shuffle: for step i, j = i + uniform(n − i) over the half's n pixels. uniform(n) reads only ceil(log2(n)) bits and rejects values ≥ n.

  4. Each slot's 264-bit record is written bit by bit into its chosen pixels, in draw order. Roughly half of them already have the right color and do not change. A slot without a secret gets a random record at positions from a random key, so images with one or two secrets look the same. Extraction derives one key from the passphrase and reads 264 bits from each slot.

For plausible deniability there is no header, length, type, version or checksum, and both slots are always written. Typical use: a decoy secret in one slot and the real one in the other, each with its own passphrase. Revealing one passphrase shows its slot, while the other slot only shows meaningless bits, exactly as it would if it held random fill. Limits: deniability holds only when the payloads look random, such as one-time-pad shares or other encrypted data stored as hex, since readable text identifies itself. Bits read with a passphrase that was never used reflect the image's brightness (for example mostly ones in a light image) rather than looking uniformly random. The bitmap must have at least 128 + 2 × 264 = 656 pixels. Resizing, recompressing or re-dithering the bitmap destroys the data.
