LSB image steganography

Hide ASCII text or raw bytes in the least significant bits of an image. A passphrase deterministically scatters the bits across the pixels. Everything runs locally in your browser; nothing is uploaded or saved by the page.

Operation

Payload format

The passphrase selects which pixels carry data. Without it the hidden bits cannot be located.

Result

Download

PBKDF2-SHA-256 · 600,000 iterations · random 16-byte salt · AES-256-CTR keystream RNG · Fisher–Yates sampling · 3 bits per pixel (R, G, B). The output is always a lossless PNG; re-saving it as JPEG, resizing, or sending it through apps that recompress images destroys the hidden data. The payload itself is not encrypted: anyone with the passphrase can read it. To protect the content as well, encrypt it first with Secure file encryption and hide the result as hex bytes. Browsers that randomize canvas reads (e.g. Brave, Firefox with resistFingerprinting) cannot be used.

Embedding algorithm and format

Pixels are numbered in raster order (left to right, top to bottom). Only fully opaque pixels (alpha 255) are used; other pixels and every alpha value are left alone, so the set of usable pixels is the same when extracting. Each used pixel stores one bit in the least significant bit of each of its red, green and blue channels, in that order.

  1. A random 16-byte salt (128 bits, most significant bit first) is written sequentially into the first N = 43 opaque pixels. The last salt pixel uses only red and green. These N pixels are excluded from everything that follows.

  2. The UTF-8 passphrase and salt go through PBKDF2-SHA-256 with 600,000 iterations; crypto.subtle.deriveBits returns 256 bits that become an AES-256-CTR key. The RNG is the AES-CTR keystream of zero bytes with an all-zero initial 128-bit counter block (64-bit big-endian counter), consumed most significant bit first.

  3. The remaining M opaque pixels form the pool. A partial Fisher–Yates shuffle picks pixels one at a time: for step i, j = i + uniform(M − i), swap pool positions i and j, and use the pixel now at position i. uniform(n) reads only ceil(log2(n)) bits — the bits needed for the largest index — and rejects values ≥ n to stay unbiased.

  4. The record below is written bit by bit (most significant bit first) into the chosen pixels. Extraction repeats the same steps, reading the header first to learn how many more pixels to visit.

Byte offset Bytes Field
0 4 Magic: ASCII STEG
4 1 Version: 1
5 1 Payload type: 0 = ASCII text, 1 = binary (from hex)
6 4 Payload length in bytes, unsigned big-endian
10 4 First 4 bytes of SHA-256(payload)
14 Length Payload bytes. Hex input is stored as the raw bytes it represents, not as hex characters.

Capacity in bytes is floor(3 × M / 8) − 14. The checksum detects a wrong passphrase or an image that was modified after embedding; it is not a cryptographic authenticator.
