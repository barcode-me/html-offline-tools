Obfuscated PDF documents

Turn ASCII text or hex bytes into an ordinary-looking PDF, such as a math exercise whose large numbers carry your data. Restore mode puts the numbers back together. Everything runs locally in your browser; nothing is uploaded or saved by the page.

Operation
Input format

Only numbers with at least ten digits are read, in order. Shorter numbers, such as prices, quantities, dates and page numbers, and all other characters are ignored, so numbers may be separated by new lines, spaces or any other text. Do not use thousands separators.

Result

Download

The numbers are an encoding, not encryption: anyone who knows the scheme can restore the data. To protect the content as well, encrypt it first with Secure file encryption and hide the result as hex bytes. Write down or keep the PDF; the page does not store the format, so pick ASCII or hex when restoring.

Encoding format

  1. The input becomes bytes: ASCII text uses one byte per character; hex input is stored as the raw bytes it represents, not as hex characters.

  2. The bytes are split, in order, into chunks of 4 to 8 bytes chosen at random. When more than 8 bytes remain, a chunk never leaves fewer than 4 bytes behind. An input shorter than 4 bytes is padded in front with random bytes to 4 bytes.

  3. Each chunk gets a marker byte in front and is read as an unsigned big-endian integer, written in decimal. The marker is 0x01, or 0x01 plus the number of padding bytes for a padded short input. A chunk of k bytes becomes a number in [28k, 28k+1), so leading zero bytes survive and each number reveals its own length; no length, format or count is stored. Every number is at least 232, so it has 10 to 20 digits.

  4. The math template places the numbers in its text in order and uses no other digits anywhere in the document. The purchase order template shows them, in order, as product IDs; its other figures (quantities, prices, dates, PO number, addresses, phone and page numbers) all have fewer than ten digits. The email confirmation and plain URL templates both place the numbers, in order, as path segments of one or more links built from the domain you enter, such as example.com/{n}/{n}/{n}; each link holds as many numbers as fit on one line, and a new link starts once the next number would not. The email confirmation template wraps the link(s) in a short message confirming an order or an appointment, whose only other figures (an order or appointment number and a date) have fewer than ten digits; the plain URL template contains nothing but the link(s). For either one, choose a domain that does not itself contain a run of ten or more digits. The PDF uses the standard Helvetica fonts and contains no metadata. The math, purchase order and email confirmation templates are available in English and Spanish; the plain URL template has no language-specific text.

  5. Restoring reads every run of at least ten digits in the entered text, in order, as one number; shorter runs and all other characters are ignored. Each number is converted back to bytes, checked for the marker byte, stripped of it, and the chunks are joined.
